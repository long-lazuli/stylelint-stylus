## Commit Strategy

### 2 Commits Per Issue

**Commit 1: Implementation** (dev-story Step 6)
```bash
git commit -m "feat: implement feature (#001)"
```
- Created at end of dev-story
- Contains all code changes
- Issue status: 🔵 In Review

**Commit 2: Approval** (approve-issue workflow)
```bash
git commit -m "chore: approve issue #001 - mark completed"
```
- Created by approve-issue workflow
- Updates issue file to 🟢 Completed
- Records completion timestamp

### User Pushes When Ready

```bash
# After multiple issues completed
git log --oneline
# abc123 chore: approve issue #003 - mark completed
# def456 feat: add TypeScript setup (#003)
# 789abc chore: approve issue #002 - mark completed
# 012def feat: update dependencies (#002)
# 345ghi chore: approve issue #001 - mark completed
# 678jkl feat: update Node.js to 18+ (#001)

# User pushes all commits
git push
```

## Workflow Sequence with Commits

```
1. start-next-dev
   Status: 🔴 → 🟡

2. dev-story (6 steps)
   Status: 🟡 → 🔵
   Commit: Implementation changes
   
3. code-review
   Validates quality gates
   
4. approve-issue
   Status: 🔵 → 🟢
   Commit: Approval (issue file update)
   
5. start-next-dev (continue)
   Begin next issue
   
6. (User decides when)
   git push (all commits)
```

## Benefits

✅ **User Control** - Push when ready, not forced
✅ **Batch Commits** - Can complete multiple issues before pushing
✅ **Review Flexibility** - Review all changes before push
✅ **Atomic Pushes** - Push related issues together
✅ **Safety** - Can test locally before pushing
